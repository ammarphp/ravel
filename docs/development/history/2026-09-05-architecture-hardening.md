# Seven-priority architecture hardening

This development pass implements the seven engineering priorities identified in the mission and code review. Its baseline is research checkout `8d8b4b53b358c9798ae9b0d6345919c907b8639e`, compared with public release `16cfb21af04c3a375ab686e659ddb15bb2ba6c98`. Those trees shared the diagnosed behavior despite their different curated layouts. The implementation is verified for v0.4.0; the source verification record is below.

The work strengthens the scientific execution contract. It does not establish new detector acceptance, statistical coverage, unhinted autonomous performance or comparative scientific superiority. Historical scientific records and benchmark baselines remain preserved.

## The seven priorities

| Priority | Resulting behavior | Verification obligation |
|---|---|---|
| 1. Typed scientific results | Limits preserve observed/expected roles, roots, one-sided bounds, brackets and missing slots. Packs bind to exact primary inference bytes and mathematical meaning. | Engine→pack→harvest→scan→plot controls; reject conflicting aliases, changed sources, censored bands and diagnostic observed projections |
| 2. Artifact-bound certification | Approved plans pin reference populations, policies, units/basis, dependencies and served outputs; comparisons are recomputed. Known producer operands must agree with primary values. | Valid live controls plus changed references/inputs/output/producer/value/identity, omitted rows and regenerated inconsistent certificates |
| 3. Explicit normalization | Native rates are reconciled with declared generation/shower evidence and correction conventions; missing scientific quantities do not receive plausible defaults. | Nonfinite, zero, inconsistent rate/event/weight evidence, double correction and charge/topology cases; retained-data converter controls |
| 4. Capability dispatch | Registered analysis/model/detector/statistics combinations produce an inspectable exact plan. The executor directly checks its approval and scope. | All registered families through bounded subprocess fixtures; unsupported/no-backend/wrong-plan/rung/budget controls; exact plan/reuse consistency |
| 5. Grounded intake | The host agent may supply typed request-bound intent; the parser preserves negation and positive target scope. Method study creates a zero-compute proposal. | Paraphrase/negation minimal pairs, exact request spans/hash, denied/new identifiers, unsupported discovery objectives and no-compute CLI controls |
| 6. Current entry and handoff | Matching parent/repository routers lead to short operational instructions; status derives a compact packet from actual evidence. Historical boards are separate. | Cold CLI paths, stale cached approval/next-action controls, source preservation, directory/link/skill parity and claim reconciliation |
| 7. Durable execution | Attempts, failures, outputs and dependencies are recorded atomically; resume reuses only valid receipts and retains prior evidence. | Concurrent state writes/output ownership, interruption/orphan/descendant cases, stale dependencies, malformed outputs, failed validators and restart controls |

The implementation is split into narrow modules: `src/ravel/limits.py` has no inference dependency; `src/ravel/validation/certificates.py` performs declared comparison checks; native capability/normalization/execution adapters live under `src/ravel/physics/`; intent, state and process control live under `src/ravel/workflow/`. Public instructions are in [scientific results](../../reference/scientific-results.md), [durable execution](../../workflow/reference/durable-execution.md), [native execution](../../workflow/reference/native-pipeline.md) and the [CLI reference](../../cli.md).

## Independent review and repairs

A fresh reviewer examined scientific result transport, certificates, intake and claim fidelity. A second reviewer examined execution/native code authored by other contributors to this pass. Their first observations were retained separately from repair results. Existing green tests were treated as incomplete evidence.

The reviews found and prompted repairs to these concrete failures:

- A result pack could be coherently rescaled while retaining its unchanged certified source. The new identity binding checks the actual primary source and all transported numerical roles and values.
- A recognized producer's comparison value could disagree with the primary scientific field when a separate discriminator was omitted or changed. Producer adapters now require compatible identity and internally consistent mathematical representations.
- An expected-only projection exposed its pseudo-observed value as an eligible observed limit. The observed slot is now missing; the diagnostic remains explicitly separate.
- Coordinated negation and raw target extraction could add denied work or a denied analysis to the draft. Intent and target extraction now share actionable scope; forbidden discovery deliverables are also checked in host-provided objectives and outputs.
- A stage leader could exit while its child continued writing. The supervisor now checks the owned process group before reporting success and handles remaining writers as a failed attempt.
- A log path could overwrite an input, result or another stage's log. Logs are restricted and participate in output ownership checks.
- Newly documented module entry points could evade old command-spelling hooks. The executor now verifies exact bound approval directly, including the actual saved plan and scientific/resource scope.
- A WZ capability accepted inconsistent daughter topology, and the normalization reader accepted contradictory source summaries. The adapters now check registered charge/topology conventions and reconcile the actual source roles and rates.

The review also found that a recent log could be mistaken for current process liveness. The final implementation requires verified process identity. All twelve original findings were independently rechecked and closed within their recorded scope. Original temporary probe scripts and raw outputs are retained in the local release verification bundle; the repository ships the maintained regressions and review reports. The [scientific findings](2026-09-05-review-scientific.md), [scientific verification](2026-09-05-review-scientific-verification.md), [execution findings](2026-09-05-review-execution.md) and [execution verification](2026-09-05-review-execution-verification.md) retain the initial failures, positive controls, repairs and exact source hashes.
