# SFitter application operations

Use `ravel.workflow.sfitter_application` to connect whole SFitterAgents source
sessions to RAVEL's current graph and ordinary scientific-study intake. The source
tree and manifest must be the exact released235-member epoch; existing scientific
workflow, parent assignment, actor/model configuration and physical inputs remain
explicit. This source adapter uses the required SFitter workflow setup in the [installation guide](../installation.md); it installs nothing and reads no credentials.

`create` forks all agent definitions, skills, docs, prompts and own wiki state.
`context` compiles one literal actor/skill and its source-scoped orientation; the
ordinary Host action `sfitter-application-context` requires the complete explicit
input closure. `skill_graph` and `execute_skill_graph` prepare and dispatch advice
through the existing cumulative research cycle. `add_note` retains only an actual
current actor return and located citations from presented context, in a fresh
fork. Advice is not scientific review or task completion.

Prepare the existing conductor's phase context and `lead_graph` with the same
parent `goal_binding`; dispatch through `research_cycle.execute_graph` before
`sfitter_conductor.adopt`. For a `request_production` return, `plan_production`
requires one exact requested operation and a supplied complete ordinary research
design. It checks actual scientific input consumption, actor response and cost
lineage before ordinary CI1 preparation. `run_production` delegates to the normal
approved cycle runner, outside a graph dispatch on the same cycle; it is not a
new execution engine. Existing source-table, model-event and native-SFitter
operations supply the computation.

`intake_production` preserves all current native/domain concerns and the complete
parent target. Delivery-only raw output enters labeled orientation/documentation,
never accepted reusable scientific prerequisites. Scoped reusable results retain
their existing exact review authority. Neither case advances a domain phase or
closes the original task; complete domain protocol, original three roles and
parent acceptance still apply.

`original_launch_interface` declares the upstream noninteractive Linux backend
(`python -B -m launcher code`, `SFA_SESSION_DIR` and dedicated
`CLAUDE_CONFIG_DIR`). It always reports runtime unqualified. Linux/Apptainer,
matching SLURM/shared paths/auth, actual nested accounting and failure propagation
need separate qualification; original automatic installation and ignored Claude
returncode are not transferred as successful execution.
