# AgentRivet ordinary construction bridge

This continuation composes the independently cleared file importer with existing
RAVEL APIs. AgentRivet is a required external GPL-3.0-or-later
generator. The RAVEL API additions are original file/schema/workflow
interfaces; redistribution or packaging of upstream code needs its own license
decision.

## Source delivery and fresh build preparation

`ravel.physics.agentrivet_source.prepare_source_study(request, *, base_dir,
output_dir, review_policy, approval_mode='physicist')` writes the standard v2 study
input. `request` is the cleared importer request: schema_version1, routine,
translation_unit/memory/paper pins and explicit assets. The complete supplied
AnalysisModel and upstream code/physics reviews remain retained producer
declarations. HEPData URL, including null, has a declaration obligation. Cached
paper text is the paper component, not the whole Analyst prompt when HEPData
context is supplied.

The caller then uses ordinary `science.plan`, `science.approve`, `science.run`,
`physics_review.open_cycle` and role contexts. The new backend is
`analyze/agentrivet-source`, requires the existing v2 review envelope, has one
60-second source-materialization attempt, and uses the existing worker/report
path. No SDK, generator, compiler or event executable is started by this adapter.
`passed` means exact source/declaration delivery only. Its result and Markdown
report retain every declaration and all paper/API/native/output obligations.

`prepare_build(result_pin, reviewed_capsule_pin, closure_pin, runtime_pin, *,
probe, base_dir, output_dir)` produces an ordinary `routine-build` task and fresh
sealed configuration. It requires:

- The exact unreviewed source result/proposal/capsule and unchanged imported
  source/provenance facts, with no upstream or RAVEL votes carried.
- A separately supplied complete dependency/assets/source capsule. No helper
  guesses header, ONNX, reference or metadata closure from a code-approval flag.
- A closed source-closure declaration containing the proposal/capsule pins,
  reviewer label, nonempty scope conditions and exactly one disposition for every
  imported obligation. Dispositions are represented, requires_event_test or
  unserved. They are supplier assertions, not an independently authenticated
  scientific verdict. Unserved IDs remain explicit in the build binding.
- An existing byte-bound sealed Rivet runtime template, freshly revalidated by
  `routine_build.seal_configuration`; it is a runtime template, not inherited
  build or physics acceptance. Native artifact size/alias rules stay with the
  existing builder rather than the text importer.
- A fresh explicit probe for the new exact routine. Parent routine-specific
  probe arguments and execution identity are not silently transplanted.

The returned task must still go through ordinary planning, approval, actual
compiler and registration evidence, and independent build review. Accepted build
receipts can feed the existing `rivet-built` event route with a separate complete
supplied-event/RAW/final/uncertainty contract. Nothing here approves those phases.

## Upstream provider interface

`ravel.workflow.agentrivet_provider.GraphLLM` implements the upstream duck
interface `valid()` and `generate(messages, output_model=None)` without altering
the external ReviewLoop or role prompts. Construct it with a fresh Graph path,
explicit model/effort, cumulative calls/output/wall bounds, a source-pinned
dispatcher callable, and the declared upstream/dispatcher dependency source pins.
The caller supplies the dispatcher; this API supplies no provider SDK, transport,
credential lookup, installation or independent scientific actor.

Each generation uses existing `agent_graph.create/revise/prepare_external/
deliver_external`. Revisions retain the same cumulative budget, all request
messages, source pins, old responses and call records. Upstream reviewers use
Graph proposer provenance: their producer annotations do not become independent
RAVEL critic/verifier votes. Dispatch exceptions retain the ambiguous reservation
and block later stages rather than resetting the graph or retrying invisibly.
All explicit upstream roles share this declared allowance when passed the same
GraphLLM instance.

Raw C++ uses an explicit `{text: string}` JSON transport envelope. Structured
outputs adapt local Pydantic `$defs/$ref` and nullable `anyOf` to Graph's existing
finite JSON schema. Every object field becomes explicit, including nullable
upstream-default fields. Values are never filled by the adapter. Original and
adapted schemas and original system/user messages are retained. Other unions,
external references and recursive schemas refuse before dispatch. This is a
declared protocol adaptation, not the original upstream provider wire protocol.
Nullable enums and constants retain exactly the original nonnull constraint
intersection plus the explicit null arm; an incompatible enum/constant permits
only that null arm. The global Graph validator is unchanged.

`valid()` establishes source-contract readiness only. The dispatcher still needs
its own installed runtime, loaded dependency, endpoint/model, capacity, actual
request/response, deadline and ownership qualification. Graph's external output
reservation does not hard-enforce inference tokens or cancel remote inference.
The Graph wall starts on the first actual Graph preparation; upstream source
setup/queue/admission and downstream native wall require explicit outer accounting.

## Controlled route and its limits

The retained initial 40 controls cover the 19 cleared portable importer cases plus 21
ordinary source/backend/build preparation, provider, finite schema and connected
released-loop cases. They use actual ordinary plan/approval/open_cycle/source
materialization/build sealing functions. The stage receipt and runtime/tools are
explicit inert test fixtures, not OS execution or qualified Rivet. No votes are
submitted; the review cycle remains pending.

The separate released-loop control executes the exact pinned upstream Agent,
ReviewLoop, Memory, role factories, schema declarations and prompts. Seven canned
responses give two revisions, preserve the unresolved physics advisory at the
upstream stopping point, and feed its literal outputs to the same ordinary source
route. Its BaseModel is explicitly a deterministic schema-only stand-in because
the actual verification environment lacks Pydantic. Neither upstream dependencies
nor genuine extraction, model behavior, compiler success or physics are qualified.
Production adapter modules contain no upstream AST bodies.

The failed development harness runs and missing-Pydantic collection refusal are
retained. The final pass is engineering composition evidence. It is not a
complete paper-to-executed-routine result.

The narrow successor additionally passes the exact unchanged nullable-enum
review witness and 12 enum/constant/intersection/JSON-equality controls: 53 total.
Only the finite schema adapter changes; source/build preparation, Graph accounting
and the global output validator remain byte-identical to the reviewed predecessor.
