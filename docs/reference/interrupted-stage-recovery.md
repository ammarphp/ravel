# Interrupted attempts: failure is separate from recovery

A recorded RUNNING attempt can outlive its supervisor. The generic host recovery code knows a child PID, its start identity, and one process group. It does not possess a complete descendant census: a descendant can start another group or session. Observing ESRCH for the recorded leader and no active members in its recorded group therefore cannot establish complete containment.

This source change records that interruption as **failed, exit 130**, after the existing host-before-guest barrier. It preserves the exact complete preterminal record in `logs/execution/<stage>/<attempt_id>/interrupted-preterminal.json`, bounds that metadata read to 64 MiB, rejects linked/changed metadata, and binds its hash and size in `interrupted_finalization`. The failed record keeps `requires_recovery: true` and `descendant_containment: not_established`. No scientific output snapshot or success receipt is generated. Partial files stay in place; the original attempt ID, original scientific diagnostics, charged attempt token and attempt journal remain intact.

`stage_supervisor.recover_previous_attempt(rundir, stage, grace=...)` owns the existing stage lock and performs recovery only. `science.run(..., resume=True)` uses this barrier before any current plan check. Repeated recovery of the new held failure verifies its preserved snapshot and raises again. An empty group or a changed cleanup Boolean cannot clear this marker. A missing recorded child, unreadable/reused identity, wrong group, unknown census or unresolved guest also blocks launch; those observations do not receive the new absence-based negative-finalization classification. Existing verified live-owned group cleanup and legacy already-terminal failed records retain their scoped behavior.

A known owned guest is still inspected after host custody fails. A stopped guest alone cannot establish host descendant containment. Conversely, unresolved guest identity/recovery prevents the new failure transition. The existing live host fence, saved job/approval bindings, exact CID/name/image/label checks and guest cleanup reserve remain unchanged.

## Actionable operator route and required evidence

There is no new receipt-only bypass or generic containment-proof importer in this patch. Keep the run held, inspect the retained preterminal snapshot and independently retained outer supervision evidence, and account for **all** known escaped groups and guests. Do not delete the state, token, marker or snapshot to resume. Root machine recovery is authorized operational action; it is not authenticated human or physicist review.

The retained actual SFitter recovery script `root-execution-v1/recover_interrupted_attempt.py` is an existing **run-specific** route. It binds an exact request, old/current record, outer receipt and child identity; acquires `logs/science.lock` then `logs/execution/science.lock`; queries every explicitly retained outer owned group; and records a negative terminal result. It was used by root on the original interrupted run. Its assertion is scoped to the observed owned groups; it is neither a generic proof of complete descendant containment nor a safe command to apply to another run. This patch does not re-execute or rewrite it.

Before a future source-bound operator routine resolves the new marker, its independent review must establish a complete launch lineage/containment envelope, or explicitly admit a narrowly scoped operational residual risk outside this automatic path. Minimum evidence includes the exact current ledger/attempt/preterminal pins, launch and supervision source/selection pins, process start identities and parent/group/session transitions for every observed descendant, completeness evidence for that population, a fresh absence/fence observation for each owned group, and exact guest identities plus producer-before-guest closure where applicable. Unknown, reused, live or unobservable populations remain held. A JSON assertion that a population is complete is not evidence that it is complete.

`external-cleanup-evidence-proposal-v1.json` sketches the finite record shape for that future review. It is unresolved and not consumed by this implementation. Root selects and admits any concrete operational remedy. Even resolved cleanup would not refresh compute approval or reset attempts: ordinary accepted reuse or an admitted correction is separately required for a spent science attempt. No outputs from the interrupted attempt are adopted as a successful computation.

## Evidence boundary

Modeled source tests establish durable negative status, no relaunch, preserved budget/history, namespace/output custody and neighboring host/guest guards. They do not exercise OS process escape, native libraries, guest clients or science. The actual SFitter interruption returned no native result vectors and has no numerical or physical interpretation. Its original outer-timeout receipt, root-scoped recovery and intake remain immutable.
