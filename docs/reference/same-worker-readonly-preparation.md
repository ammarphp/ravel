# Same-worker read-only preparation

Ordinary scientific workers can retain one independent observation across full
worker admission and a source-declared pure calculation. The first adopters are
`research-comparison` and `derived-quantities`. The public operation and science
CLI are unchanged; there is no caller flag, extra approval or research scheduler.

The worker waits for its supervised registration before constructing an inert
owner. Descriptor discovery occurs only at the existing adapter-resolution point
inside ordinary admission. Both original and effective tasks receive their own
input callbacks. The effective task alone is calculated. Every original plan,
approval, attempt, correction, source, runtime, process and scientific input check
remains required. Producer plans use their own run-bound Sessions with full
semantic rechecks, not the comparison worker's task context.

`READONLY_WORKER_V1` is a source-owned `ReadOnlyAdapterV1` declaration binding the
public and private callable identities, three explicit context-taking hooks and
the old output-directory ownership policy. It is neither execution authority nor
a proof that arbitrary Python code is pure. Initial callable injections, unknown
adapters, schema 1 and effectful/helper/`run_in_worker` routes retain their full
existing path. Late replacement of an enrolled callable refuses. No adapter is
imported from an unverified effective specification just to select this protocol.

The owner freezes the complete participant and callback roster while all Sessions
remain live. It drains every semantic callback once, then checks every Session's
original file/hash, ancestry, inventory, observed absence, ledger, runtime and
mutable-value commitments. Final reads may add observations through existing
participants; old baselines cannot be refreshed. New participants and callbacks
after freeze refuse. No convergence loop, parent proof, cross-process transfer,
cross-call cache or atomic-filesystem-snapshot claim is introduced.

Worker PID, parent, process start identity, exact selected attempt/correction,
descriptor and callable ownership remain bound through release. A fixed ending
recheck precedes the detached bundle. Failure closes every acquired participant
without discarding the primary failure; cleanup failures are retained as notes.
Ordinary Session `finish()` and standalone adapter APIs keep their previous law.

The detached bundle contains only independent JSON bytes and intended artifact
bytes. Resources close before output-directory creation. The ordinary worker
still writes its existing common result, recipe, figures, verification and
check-in, then checks adapter artifacts and the common result against intended
bytes. A destination that appears late, failed writer or late result change cannot overwrite
an earlier accepted artifact, refresh the calculation or refund an attempt.

Resource ceilings are 32 participant factories, 129 distinct Sessions, eight
adapter artifacts, 128 MiB result JSON and 256 MiB complete delivery bytes. A whole
population exceeding these ceilings refuses rather than truncating. The supplied
arithmetic, status/unknown/worse outcomes, covariance, units, output filenames,
encoding and scientific limitations remain unchanged. Neither adapter's result
acquires physics validation or scientific acceptance.

All calculation and ending work remains inside the existing supervised stage
clock. No timer is moved or increased. Root-owned controls, original regressions
and matched actual timings are required before numerical equivalence, connected
runtime success or performance improvement can be claimed. The source author has
not imported product code, collected or run tests, or launched a scientific job.


The read-only branch enrolls the source-owned process identity observer. An
initially injected observer receives the unchanged full worker fallback; a late
replacement refuses. No initially custom callback runs after the terminal tail.
The worker also retains the exact three forbidden-envelope `Path.exists()`
observations, including false for dangling links, and the admitted review
registration/head/event population. Its actual current launch/review law runs
again during semantic draining; all positive and negative observations remain
live through the complete joint terminal check. These are worker-local checks,
not changes to public launch policy or default Session `finish()`.

The successor controls retain all original 57 prospective cases. The four driver
cases use the canonical process observer with disclosed engineering admission;
separate controls assert initial injected fallback and late replacement refusal.
Connected replication controls use the existing authenticated request producer,
full original/fresh reconstruction and caller-issued producer semantic rechecks
through the actual shared owner. Their synthetic engineering review does not
establish scientific acceptance or timing. Every new control is unrun by author.
