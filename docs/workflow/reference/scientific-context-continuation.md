# Finite scientific retained-context continuation

An actual scientific_context_request is nonvoting. The ordinary review journal remains pending; the actual model-call receipt stays in its original Graph and any campaign reservation. advance returns that request once. It does not repeat the role, grant execution permission, or substitute a repair/new experiment.

prepare_role(..., evidence_pages=[...], max_context_reworks=N) predeclares the finite allowance before the first call. Legacy omitted arguments retain schema1 and one-call behavior. New requests use schema2. Model selections use one closed object with kind, artifact_id, section, offset, max_bytes, query; unused fields are null. The manual initial-page API also accepts the original exact artifact/index selection shapes. At most32 pages per presentation, 65536 source bytes per page, at most8 followups and 2000000 serialized Host request bytes are allowed; the actual Host inline budget must also accommodate every required page/core. Index pages supply discovery, not scientific content.

The explicit caller sequence is prepare_role → execute_role → consume → continue_role(binding, new_directory) → execute_role(new_binding) → consume. Public CLI prepare-role/advance accept --evidence-pages JSON_FILE and --max-context-reworks N. continue-role accepts --binding ORIGINAL_BINDING --out NEW_DIRECTORY. All dispatch/consume commands retain their normal --rundir, host configuration and authority gates. continue-role itself dispatches nothing. It copies the already role-projected packet, preserves its complete original artifact census and private predecessor, presents the actual nonvoting request, current action core and exact selected pages, and revises the same Graph. It never reads a critic's unprojected run or another role's private judgment.

Fresh review receipts must actually present the exact current subject, core and every retained selected-page wrapper. Located citations are authenticated JSON pointers into the actually presented core/artifact wrappers; an index page must not supply scientific credit. The existing exact-case node/edge/assumption audit and ordinary authority gates remain required. Custody and software controls do not establish scientific truth, actor authentication, blinding of empirical results, or all-content model reading.

Shared campaign API: revise_graph(cycle_root_or_None, graph_root, new_spec, *, expected_spec_sha256, predecessor_result_pin, reason); validate_graph_reservation(authenticated_cycle_state, graph_root, current_spec). predecessor_result_pin is the canonical absolute {path, sha256, size} result identity. Only one existing model node's packet and instructions can change. Model, schema, action, inputs, dependencies, role, parent contract, graph identity and all resource ceilings remain exact. The original reservation SHA stays untouched; authenticated pending/admitted cycle events append the finite revision chain. Existing cumulative usage, Graph start time and original campaign deadline remain unchanged.

Before revising, continue_role retains prepared-continuation.json containing the exact new binding/spec, old specification SHA, predecessor result pin and reason. If interrupted, inspect the retained pair and invoke the same revise_graph arguments; no new reason/spec/result or renewed budget is admitted. Exact pre-Graph and post-Graph/pre-cycle-admission states recover; exact spec-after/state-before Graph writes recover only from the retained full predecessor checkpoint and immutable new spec. A foreign/changed pair refuses. After the admitted revision, use the prepared binding for the explicit next call; do not call continue_role again on the superseded predecessor. This is a local exact-pair recovery contract, not a general transaction system or permission to adopt old clocks.

Manual failed-stage diagnostics, metareview, fresh independent critic/verifier roles, recomputation, repair admission and scientific experiments keep their existing separate paths. This implementation provides no model/provider/native execution evidence. The SFitter domain can call the shared APIs, but its separately frozen integration and charged whole256 followup require the root-owned joined check.


Shared checked admission is a source-defined permission to refresh retained evidence, not a caller authorization flag. The exact authenticated completed predecessor must be scientific_context_request with null verdict/proposal/scope and empty findings/closes, or the original source-defined SFitter request_context proposal with empty handoff/documentation/production. A normal vote never authorizes a context revision. The common verifier reconstructs every scientific selected-page wrapper from the previous role-projected packet and actual requested ranges, exact predecessor receipt, cumulative page/source-byte accounting and current core; actor/case/source/anchors and the complete original projected census remain fixed. SFitter uses its separately source-bound packet_capture law for both packets, preserving original input catalogue, context, phase/target, instructions and exact requested context_pages. SFitter pages are per-call selections; they do not grant earlier stateless calls' content credit. Historical scientific requests/pages remain retained as explicit predecessor artifacts.

The common API revalidates this authorization before admission, exact pending-pair recovery and read-only admitted-chain acceptance. It never accepts an event merely because it exists. Standalone callers pass None as the cycle root. Canonical agent_graph.revise accepts optional expected_spec_sha256 and expected_state_sha256; both are checked after loading under its existing run/state locks and before invalidation. Legacy calls that omit these arguments keep their original behavior. Checked standalone and campaign continuations pass both fences, so a concurrent rework or result/spec replacement refuses. Original clocks, resource ceilings, model/actor/node/schema/raw inputs/dependencies, original parent and cumulative charges remain unchanged. Campaign recovery can complete only its retained authenticated spec-after/state-before pair; standalone generic interrupted writes still fail closed rather than gain a new journal or recovery authority.

V1 source and independent SEND_BACK remain immutable. V2 closes the missing shared nonvoting/page authorization and atomic predecessor fence in pure software controls. The separately frozen SFitter V2 call sites use this exact API, but the root-owned composed campaign-bound whole256 page check and independent shared-source review remain required before promotion. No scientific/model/provider/native efficacy is established.


V3 requires an explicit well-formed actual Host evidence_presentation for every opt-in prior continuation admission and final scientific consume. Missing observations never receive content credit from manifest inline declarations. The observation must identify the exact packet and serialized context, provide typed unique subject digests and bounded indexed presentation metadata, and disclose deferred_content_read=false/all_content_read_by_model=false. Prior scientific requests must actually present the exact action, current core and every retained selected page; SFitter requests must actually present the original public core and every selected page of that call. Final scientific receipt subjects must correspond to the same explicit observation and cover the current core/all retained selected pages. Generic legacy role_receipt behavior is unchanged. V2's static R3 finding and all previous source/observations stay immutable; fifty pure controls, including twelve missing/malformed/core/page negatives, establish this software scope only.


V4 binds the SFitter target exactly as its real producer: the retained source core contains context.target, and proposal_schema uses agent_graph.digest(context.target). The common verifier uses that same digest; no flattened context.target_sha256 field is assumed or introduced. A small actual producer packet exercises ordinary followup_context → common authorization and a wrong-target refusal. The failed root full256 joined control is retained; it must be rerun by root after independent source clearance. This one-line join correction changes no page/presentation/role/budget/authority law.


An already reserved ordinary role Graph without a registered experiment
association can call `scientific_judgment.continue_role(binding, out,
campaign_root=existing_campaign, ...)`. The source verifies the exact current
reservation before admitting the actual nonvoting requested pages. Supplying
both this explicit campaign and the older experiment association is ambiguous
and refused. Actor, source, objective, role and original calls/reworks/deadlines
remain unchanged; no new campaign or authority is created.
