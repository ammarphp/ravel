# Source context to an ordinary research study

`ravel research-tools` connects the existing scientific context compiler, typed
blueprint, Graph/Host, portfolio admission and research cycle. It uses the same
journal, parent assignment, cumulative resource ledger and ordinary scientific
approval/review gates. A concrete supplied intervention needs no model turn.

Use an existing research cycle and a complete source-bound blueprint. Every pin
has `path`, `sha256` and `size`; request JSON is consumed through the existing
bounded CLI reader. The `plan-workflow` request supplies `root`, `blueprint_pin`,
`choice_pin`, fresh `output_dir` inside the cycle, fresh scientific `rundir`, and
an explicit `max_wall_seconds`. Optional `api_documents` and `queries` follow the
scientific-context schema. Run:

```console
ravel research-tools plan-workflow --request /absolute/path/arguments.json
```

The fixed sequence extracts actual adapter/lifecycle definitions, retains the
whole requested quantity and compatibility census, materializes the declared
input choices through the Host, admits their portfolio, selects with the existing
controller and creates a real unapproved ordinary plan. The returned handoff lists
the existing run/observe/adjudicate commands. Its approve command is a prefix:
append `--quote` with actual CHECK-IN 1 assent. No approval or scientific worker
runs here. If an older branch is preferred or resources are exhausted, that fact
remains visible; the connector cannot force the new branch or reset expenditure.

For a designer turn, `choice-spec` builds the existing finite model schema with
all actual APIs, current premises and live knowledge contexts. Execute it through
the existing charged Graph API, then `research_tools.prepare_choice` authenticates
the real result and its full input census. `materialization-spec` and
`admission-spec` expose the same deterministic operations individually. Missing
APIs stay explicit questions to resolve; missing prior evidence does not veto a
hypothesis. Typed slots restrict changes to supplied inputs, not adapter code,
policy, resource ceilings or parent obligations.

After actual ordinary execution and role review, `recovery` prepares the existing
failed/result feedback context for an explicit fresh typed blueprint. Criticism,
negative observations, reopened premises, domain/convention conflicts and
unknown checks remain in the same cycle. The scientific-judgment tools consume
and improve those results; they do not need a second controller. New context is
checked at admission, selection, planning, run and evidence use. Source drift,
including restored-byte changes during materialization, refuses the affected
operation and preserves its original failure.

Materialization captures the existing blueprint outputs and its commitment,
then the emitted tool portfolio, before writing the final tool receipt. A
successful return requires their original bytes and file identities to remain
current, the receipt to match the exact serialized result, and the output tree
to contain precisely the emitted files and their directories. Partial outputs
remain available after a refusal. These checks cover the captured operation;
they do not claim atomic filesystem isolation or authenticate a later launch.

The experiment's existing `input_pins` inventory contains the complete tool
context closure: bundle, API request, compiled API context and every source pin.
Portfolio presentation, exposure classification and supplied revision admission
use that same inventory. Methodological review therefore receives the bytes used
to choose the study. The ordinary solver input inventory remains the actual
adapter dependencies; these additional pins describe and guard design context.

## Retired backend operations

`backend-spec`, `backend-execution-spec` and `backend-result-context` refuse. The external cosmology agent
backend route was dropped, so these operations return the plain reason recorded in
`src/ravel/workflow/cosmology_backend.py` and no source or runtime is fetched or loaded. Cosmological calculations
run through the `cosmology-solver` operation (CAMB, CLASS, Cobaya).

## Scope

This is a connected infrastructure operation. API selection, plan/result separation and concrete tool
handoffs are implemented through ordinary Ravel operations. It does not qualify provider packages,
implement every upstream service, or establish a research-performance advantage. Optional phase eligibility and
complete resource/report bridges compose through existing blueprint, selection,
feedback and synthesis interfaces; their separate domain contracts remain in
force. Cheap-model experiments and general speculation are not mandatory steps.
