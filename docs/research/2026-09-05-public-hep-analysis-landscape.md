# Public HEP analysis landscape for Ravel expansion

Date: 5 September 2026. This is a research survey and candidate census, not a certification report or an executable analysis registry.

The strongest near-term expansion is to reuse published statistical models with explicit signal-template contracts. A broader Ravel should also support measurement fits, lifetime-dependent efficiencies, finite-width resonance shapes, dark-shower signatures and open-data studies. These require different scientific representations. Routing every request through a positive counting signal and a single upper-limit scalar would lose essential physics.

The evidence package contains **26 curated candidate routes**, **45 ATLAS probability-model index entries**, and **16 successfully pinned public repositories**. One additional query records an absent historical branch. The two analysis counts overlap and must not be added. None of the curated candidates was executed or newly scientifically validated in this survey. Nine identify a plausible existing statistical component, thirteen require an adapter and scientific closure, and four require substantial method or data-analysis work. These counts describe development routes, not analyses that Ravel currently serves.

Machine-readable records are in [the survey evidence directory](../../evidence/audits/2026-09-05-analysis-landscape/). The [candidate census](../../evidence/audits/2026-09-05-analysis-landscape/candidate-census.json) records artifact availability, routing tier, model/detector/statistical limitations and admission requirements separately for every entry. The [source ledger](../../evidence/audits/2026-09-05-analysis-landscape/sources.json), [repository pins](../../evidence/audits/2026-09-05-analysis-landscape/repository-pins.json), [documentation checks](../../evidence/audits/2026-09-05-analysis-landscape/documentation-checks.json), and [retrieval results](../../evidence/audits/2026-09-05-analysis-landscape/metadata-fetches.json) delimit what was actually inspected.

## Scope and evidence method

This is a purposive survey of publicly reusable LHC material, selected to expose substantially different scientific requirements. It covers the requested tool families and concrete examples from searches, measurements and open data. It does not claim all HEP studies, all public likelihoods, all experiments, or even all analyses supported by the tools listed below. Heavy-ion, flavour, neutrino, lepton-collider and cosmological analyses would need dedicated surveys and adapters. A portal's supported collaborations are not a claim that this survey assessed those experiments.

Primary papers, experiment pages, maintainer documentation and public data portals support availability claims. Scientific admission requirements below are this review's judgments. Repository identities were obtained with `git ls-remote`; selected README documents were read at those revisions and their hashes recorded, without retaining competitor code. A pin identifies a revision, not an installation, an executed benchmark, or the revision behind every separately hosted documentation page.

The public ATLAS probability-model index was downloaded and contains 45 entries: 24 TOPQ, 17 SUSY, two EXOT, one HIGG and one HDBS. It is useful discovery metadata, but its entries do not enumerate workspace payloads or establish that every record is a drop-in HistFactory model. [Maintainer index](https://pyhf.github.io/public-probability-models/atlas.json).

Four attempted HEPData record downloads—compressed spectra, multi-b gluinos, non-resonant semi-visible jets and CMS disappearing tracks—returned HTTP 403. That is an acquisition failure in this survey, not evidence that the experiments withheld or never released the resources. Exact response results are preserved. The census therefore labels indexed resources as **index confirmed**, and does not label uninspected likelihoods, maps or covariance arrays as downloaded. HEPData documents programmatic record/search endpoints and versioned data retrieval; each eventual adapter should retain record version, table/resource identity and content digest. [HEPData formats](https://www.hepdata.net/formats).

| Contur / Rivet | Compare BSM predictions with preserved collider measurements using particle-level analysis routines. | HEPData / CERN Open Data | HEPData serves published numerical results and auxiliary resources. CERN Open Data also exposes collision/simulation datasets and preserved software metadata. An immediate compatibility issue illustrates why repository and database identities both matter: SModelS 3.2.0 replaces older statistical-model fields with `regionMappings`, `regionSets` and `statModels`, changes likelihood interfaces and adds ONNX surrogate models. An adapter written against historical JSON-field names needs an explicit migration, and surrogate predictions need a recorded approximation domain. A live analysis-list page initially returned an older cached version during this survey; no aggregate SModelS analysis count is used here. [Release notes](https://smodels.readthedocs.io/en/latest/ReleaseUpdate.html).

## Candidate census and executable routing tiers

**E0** means discovery metadata only. **E1** means a current Ravel statistical component is a plausible target after exact artifact, format and benchmark admission. **E2** means a documented public artifact or external executable route exists, but Ravel needs an adapter and scientific closure. **E3** means substantial new method or data-analysis work, suitable for research planning. None means “approved to execute” or “validated analysis.” Every curated row remains a candidate; all 45 additional index rows remain E0 until inspected individually.

The P-series and M04/L03/L04 identities come from the [public model index](https://pyhf.github.io/public-probability-models/atlas.json); the census retains exact experiment and data-record URLs for each. Index membership supplies discovery evidence only. Their common next step is a versioned workspace manifest and benchmark replay, followed by independent signal acceptance validation where generated events are used.

The WW and Wγ measurements demonstrate why measurement reuse needs its own route. ATLAS specifies a fiducial electron-muon final state and jet veto; CMS uses an angular observable to recover sensitivity to SM–EFT interference. The reviewer consequence is to preserve signed coefficient contributions and correlated observables rather than reinterpret them as independent positive signals. [ATLAS WW](https://arxiv.org/abs/1905.04242v2), [CMS Wγ](https://arxiv.org/abs/2111.13948v2).

ATLAS's OmniFold result presents a particle-level event representation rather than a fixed list of histogram bins. A new observable must remain a function of that representation and within its measurement scope. The public reuse repository was pinned at `881209c512c4ba7c4745874be57c93b4bf424a58`; its presence does not establish that a new observable has a valid uncertainty estimate. [Paper](https://arxiv.org/abs/2405.20041), [pinned reuse repository](https://gitlab.cern.ch/atlas-physics/public/sm-z-jets-omnifold-2024/-/tree/881209c512c4ba7c4745874be57c93b4bf424a58).

For disappearing tracks, the SModelS listing explicitly identifies efficiency maps for ATLAS-SUSY-2016-06 and CMS-EXO-19-010. Their payloads were not downloaded here. Map interpolation must carry its declared variables and domain; mass/lifetime reuse cannot silently replace event boost distributions or tracking response. [Map listing](https://smodels.github.io/docs/ListOfAnalyses), [ATLAS analysis](https://atlas.web.cern.ch/Atlas/GROUPS/PHYSICS/PAPERS/SUSY-2016-06/), [CMS analysis](https://arxiv.org/abs/2004.05153).

The resonance candidates intentionally separate a narrow mediator search from published Gaussian-shaped limits. Neither establishes that a broad resonance with tails or interference belongs to its tested shape family. The semi-visible-jet candidates similarly separate non-resonant production, an inclusive resonant search, a classifier-selected search and measurement constraints. Each choice changes the accepted signal and statistical interpretation. [Low-mass photon-associated search](https://arxiv.org/abs/2408.00049v2), [dijet search](https://arxiv.org/abs/1910.08447v2), [ATLAS semi-visible jets](https://arxiv.org/abs/2305.18037), [CMS semi-visible jets](https://arxiv.org/abs/2112.11125v3), [Contur dark-sector study](https://arxiv.org/abs/2502.11237).

The anomaly entries are research routes until their training and inference artifacts are admitted. Published benchmark limits establish that the experimental methods exist; they do not establish a portable trained model or validate an independently retrained network. A method's sensitivity, mass sculpting and null calibration belong to its final frozen training/evaluation procedure. [CMS anomaly search](https://arxiv.org/abs/2412.03747v2), [ATLAS anomaly search](https://arxiv.org/abs/2307.01612v2).

CERN Open Data record 12360 provides a particularly useful bounded test of the distinction between documented and executable. Its ROOT workflow has named software files and checksums, and links reduced collision/simulation datasets. Its suggested `2012` Git branch is absent from the remote refs inspected here; current `master` is `ffbe653cd2774f9b30acfff77de0882fcf3d7feb`. The record separately lists a versioned archive, whose bytes were not fetched. Resolve that provenance before execution. The example omits minor backgrounds and only loosely follows the official analysis. By contrast, ATLAS's research release covers 2015/2016 collision data with simulation, but an individual research analysis still needs an exact file and calibration manifest. [CMS workflow record](https://opendata.cern.ch/record/12360), [ATLAS research release](https://atlas.cern/Updates/News/Open-Data-Research).

## Scientific priorities and architecture consequences

1. **Released likelihoods and explicit signal patches.** Start with a small set of diverse P-series records, including compressed spectra, a noncompressed electroweak channel and a heavy-flavour channel. A reusable loader should verify the release identity, schema, POI, bin order, nuisance bounds, auxiliary observations and signal/control-region patch agreement. A successful statistical replay supports numerical and central-comparison statements only; acceptance and coverage require their own evidence.
2. **Measurement and EFT contracts.** Add a prediction object that carries the SM term, signed interference and quadratic terms, coefficient basis/units, truncation, theory uncertainty and fiducial definition. The total expected model must remain physical in the accepted parameter domain. A coefficient interval may be two-sided or disconnected and need not have the monotonic topology of a positive signal-strength upper limit. Preserve covariance rank, normalization constraints and overlap between measurements.
3. **LLP map contracts.** Record lifetime units, lab-frame decay positions, topology, map axes, edge policy, event versus object efficiency and interpolation support. Admission needs benchmark closure across the domain being used, including failures outside it. Prompt detector cards cannot certify displaced response.
4. **Shape-based and dark-shower contracts.** Keep full shape templates, width conventions, shower model/tune, invisible-fraction convention, detector/tagger definition and background-fit prescription. Changes in width, dark fragmentation or classifier selection are scientific protocol changes, not ordinary scalar rescalings.
5. **Preserved workflows and open data.** Treat external workflow execution as a first-class route with an immutable software/data/environment manifest. Preserve dataset versions, checksums, data quality, trigger choice, luminosity and calibration records. Start with a documented bounded reproduction, then extend. A catalogue entry must fail closed when a branch, dataset, image or required calibration is unavailable.
6. **Method studies with separate calibration.** A training request should produce an explicit dataset/split plan, baseline and frozen evaluation procedure. A successful fit or attractive ROC curve is insufficient to serve a new exclusion. Require null and injected-signal validation appropriate to the final method; preserve the distinction between numerical validity, central comparison and physics/coverage claims.

These priorities are proposed engineering/scientific boundaries, not claims that a new calibration campaign has already been performed. They follow the experimental-reuse motivation in the [LHC Reinterpretation Forum recommendations](https://arxiv.org/abs/2003.07868), while making the implementation consequences explicit for Ravel.

A scalable public registry should therefore store at least five independent states: source discovered, artifact obtained, adapter executable, benchmark reproduced and scientific domain validated. Each transition needs its own evidence. Unknown, missing, failed and out-of-domain cases remain visible in the denominator. Catalog size, tool availability and unit-test success must not promote an entry to “served.”

## Deliverable verification and limits

The evidence validator checks unique IDs, declared enums, source references, repository SHA identities, metadata hashes and the candidate-only status of this dated survey. It also ensures the 45-entry discovery snapshot is kept separate from the 26 curated routes. Its adversarial controls reject unsupported validation promotion, missing source IDs, contradictory execution admission and mutated saved metadata. This verifies the integrity and internal consistency of the survey, not any external scientific result.

Run from the repository root with a Python 3 interpreter:

```text
python evidence/audits/2026-09-05-analysis-landscape/validate_catalog.py
```

The displayed relative command assumes the repository root; the script itself resolves its sibling evidence files independently of the working directory. No generators, detector simulations, model training, external workflow submission or likelihood benchmark campaign were run in preparing this survey. Ravel's current capability and run-specific evidence remain authoritative over this dated proposal.
