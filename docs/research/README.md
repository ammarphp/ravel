# Research and evaluation

This section records the scientific questions behind Ravel, earlier evaluations,
and proposed experiments. Use the [workflow guide](../workflow/README.md) for
operating instructions and [validation results](../validation/results.md) for
artifact-backed measurements.

The [public HEP analysis landscape](2026-09-05-public-hep-analysis-landscape.md)
surveys 26 concrete candidates, a separate 45-entry public-model index, and pinned
tool repositories. Each candidate records available artifacts, required adapters,
and unresolved physics/statistical conditions. Discovery does not grant execution
or certify an analysis.

The [RRR diagnosis and proposed campaign](2026-09-05-rrr-diagnosis-and-research-program.md)
connects measured pipeline failures to a staged physics and capability program.

## Reliability study

The [competitive assessment and prospective experiment design](2026-09-05-competitive-design-and-validation.md)
compares pinned versions of related agentic HEP projects and proposes a crossed
study of instruction and enforcement effects. Its experiment has not been
externally preregistered or executed by the registry tool.

The [governance experiment utility](../../benchmarks/governance/README.md) freezes
an assignment roster and checks complete outcome accounting. It provides
descriptive estimates, not evidence of efficacy or a causal conclusion. It does
not launch agents or supply the independent physics oracle.

## Historical evaluations

The [routing evaluation](routing-evaluation.md) and specialist reviews in
`reviews/` record earlier investigations. The historical seven-case routing board
included a directory hint; one subject also encountered an expected-answer row.
It must not be cited as a cold, unhinted full-workflow success rate. The prospective
protocol separates these earlier observations from future scored trials.

Existing agentic HEP systems overlap substantially with the broad simulation and
recasting workflow. A narrower scientific question is whether experiment-anchored
validation and artifact-bound approval improve useful, justified delegation.
The current evidence does not establish that causal benefit.

## Repository design references

The September 2026 documentation redesign inspected established installable HEP
tools without copying implementation code:

- [cabinetry](https://github.com/scikit-hep/cabinetry/blob/0252deed24451e835570619d67e60a674034d9d5/README.md): concise scope, installation, example, and documentation.
- [pyhf](https://github.com/scikit-hep/pyhf/blob/f19891b2255b9d8327ad0a2fc1d3b49664afbd9d/README.rst): concrete examples with expected output and separate reference documentation.
- [MadMiner](https://github.com/madminer-tool/madminer/blob/3e2615d0076c69e2a0e210d2ee15ebc11989e9b7/README.md): lightweight and full-physics tutorial paths.
- [Vector](https://github.com/scikit-hep/vector/blob/131c7d0d33fc30a2fd06d355da840a85e9bd10cc/README.md): documentation organized around user tasks and integrations.
- [mapyde](https://github.com/scipp-atlas/mapyde/blob/7cc0afbb52283ea2a8f4375e4063227e8e2f9b8f/README.md): visible configuration and command interfaces, with the research paper separate.

These are design precedents, not measured evidence of usability or adoption.

- [Physics fidelity and validation landscape](2026-09-05-fidelity-and-validation-landscape.md): pinned comparisons, implemented lessons, and future calibration studies.
