## The bar — R1–R8 + R9 (the definition of "done"; reference)
Synthesised from arXiv:2003.07868 (LHC Reinterpretation Forum) + 2306.11055. A framework fit for wide
use + publication must, for **any** analysis with a routine:

| # | Requirement |
|---|---|
| R9 capability coverage | **(audit v2)** the demand-side board: each of the 7 real physicist-prompt classes is served / served-with-refusal / partial / unbuilt per `framework/capability-matrix.json`; the audit headline carries this dimension so engine-readiness can never masquerade as project-readiness |
| R1 physics validation | acc×eff reproduces the published cutflow for a benchmark point to a stated (tiered) tolerance; particle-level checks before detector sim |
| R2 statistical rigour | use the analysis's **own** statistical model (published likelihood; else observed+background) and reach the true 95% CL crossing; never hand-rolled |
| R3 complete data | use the analysis's **complete** published numbers (SR yields, cutflows, covariance), not only what one tool bundles |
| R4 complexity | handle multi-region / multi-bin / control-region / jigsaw analyses as first-class |
| R5 provenance | every run records tool+routine versions, σ-source (LO/NLO+NLL), data-source, seeds — reproducible |
| R6 visual fidelity | the overlay reproduces the experiment's published figure (same axes/binning/data) |
| R7 coverage + cross-check | breadth across ATLAS+CMS; an independent recasting cross-check (SModelS/MA5/CheckMATE) |
| R8 documentation + citeability | per-analysis docs, reproduce recipes, versioned + citeable |

`python framework/audit.py` scores each dimension into `AUDIT.md` with a readiness %. Run it before and
after each session; open gaps live in `KNOWN-LIMITATIONS.md`.
