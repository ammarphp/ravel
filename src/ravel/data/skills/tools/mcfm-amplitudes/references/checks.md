# Checks and evidence: mcfm-amplitudes

`oracle_check` is same-program consistency. `spin0_amplitudes.closure` is a
scoped same-point alignment check. An independent cross-check is a separate
operation with source identity and convention, not an automatic consequence of
either. Keep complex phases, reference amplitudes and cohort covariance.

| Advisory ID | Candidate check | Evidence needed | Current enforcement |
|---|---|---|---|
| AM-A1 | Compare direct stored-point absolute estimators with RAW histograms after each admitted event/shower/routine path, including cancelling and zero signed sums | Named-stream mapping, attempted-draw counts, RAW histogram units, matched events and covariance | Partial: `weighted_events.normalize_raw` implements the current estimator and `amplitude_predictions.block_vectors` refuses failed draws; every new response path still needs an independent chain witness |

RAVEL sources: `amplitude_basis.py`, `amplitude_records.py`, `amplitude_store.py`,
`amplitude_integration.py`, `amplitude_predictions.py`, `amplitude_crosscheck.py`,
`weighted_events.py`, `spin0_amplitudes.py` and `amplitude_cli.py` under
`src/ravel/physics/`. External component hashes and runtime belong to the native
execution contract. Changing them invalidates affected results.


Installation checks use `ravel-mcfm-amplitudes-check`, generated by the installer.
It runs the pinned image's check script and prints one JSON line; only
`"status":"passed"` succeeds. Doctor also requires the program and build
receipt in the build tree. Its failure gives the exact install rerun command;
a stopped Podman machine gives `ravel-podman machine start ravel`.

The installer saves the image build receipt, a validated launcher with pinned
client and resources, and `<prefix>/installations/mcfm-amplitudes.json`.
The integration mode fills omitted backend fields from this record and pins it
as a stage input. A changed record, program or build receipt is refused. Image
adoption requires matching Containerfile/context hashes, base digest, platform
and engine presence. Failed build trees are retained, never deleted.

On Linux x86_64 the same wrapper runs the check script on the host with the
compiler-bootstrap toolchain first on `PATH`; the installation record then names
a `native` launcher and pins MCFM's runtime files.

`scripts/validation/qualify_mcfm_amplitudes.py` runs an installed program as a
native stage runs it and applies `oracle_check`, the spin-0 closure, a repeat of
one block and a point evaluation of block points. It recomputes the declared
safety cuts from every stored point and excluded draw, accepts the block through
the store writer as the integration mode does, re-evaluates excluded draws in point
mode (each must be excluded again) and reports the measured excluded share of the
draws, the integration factor and the program's own weight under `safety`.

The installation check establishes loading and byte identity. A point-oracle
study tests supplied numerical points. The manifest records the qualification of
the Linux x86_64 native route; the macOS container route remains built-unqualified
until its own run is recorded, and the independent cross-check remains separate.
