# Native event-shape source construction

`ravel.physics.rivet_shape_component` emits Rivet Sphericity, Thrust and Spherocity constructors, native `calc` calls and explicit scalar, axis or const-object access. It performs no event-shape arithmetic in Python. `rivet_event_components` accepts an optional `event_shapes` stage after the existing particle/dilepton/FastJets/MissingMomentum pipeline. Recipes without that field produce the identical prior result.

Use `compile_component(recipe)` or digest-bound `instantiate(source, expected_sha256=..., recipe=...)`. A shape recipe has schema_version=1, kind=native-rivet-shape-components, source_bindings and nodes. Each node explicitly names id, kind, input={kind:projection|collection,id}, projection_name, r and outputs. Sphericity requires positive finite r; Thrust and Spherocity require null r. r is the native momentum-power parameter, not a weight or normalization.

A projection input must be a prior native FinalState. It emits the corresponding cached constructor and declare; a direct collection emits an uncached native calc. Supported direct types are particles, vector3 and four_momenta, plus jets for Sphericity only. Thrust and Spherocity have no native Jets overload. Optional pipeline shape inputs can consume existing particle/boson/raw collections and selected jets; DressedLeptons, pair arrays, decay tables and MET vectors are not silently relabelled as supported collections.

Every existing-source binding declares id, native type, frame=caller_supplied_no_transform, its exact definition excerpt and SHA256. Instantiation requires the excerpt to occur uniquely before the relevant source slot. This is literal source binding, not C++ type inference or proof of the complete event population. Fresh compilation and source review must verify the declaration and its scope. Caller momentum preparation, boosts, rotations, transverse projection, ghost insertion, cuts and collection ordering remain explicit original source. No automatic center-of-mass or transverse conversion occurs.

An output specifies id, native accessor and unit=1 for a dimensionless scalar or Vector3 axis. Accessor object instead requires unit=native_projection and emits a const reference to the complete native object for unchanged enclosing getter expressions. Spherocity only populates one axis in the retained 4.1.4 source: the compiler lowers spherocityAxis/axis1 and refuses its major/minor/axis2/axis3 accessors. Native empty/zero/degenerate/nonfinite outcomes and axis orientation are preserved, without clipping or invented finite values. Thrust's documented coplanar and large-multiplicity scope conditions remain native obligations.

Standalone templates contain exactly one whole-line RAVEL_SHAPE_HEADERS, RAVEL_SHAPE_INIT and RAVEL_SHAPE_ANALYZE comment slot. Source bindings must precede init for external FinalState projections and analyze for direct collections. The event pipeline uses its existing event slots. All bytes outside explicit replacement spans remain the enclosing source; arbitrary C++ parsing/translation is not provided.

Use source_capsule to create a distinct, incomplete normal capsule while retaining all original assets. The existing native_construction, routine_build and existing_events routes remain authoritative. Source types, exact installed API/ABI and include/compiler/loader closure need fresh admission. Complete original outputs, every weight, RAW/global/flow/error/mask state, counters, units, normalization, smearing, published classifiers and physical applicability are separate requirements. Full upstream routine execution is not limited to this typed construction subset. This capability supplies source; it grants no compilation, native numerical, inference or physics acceptance.
