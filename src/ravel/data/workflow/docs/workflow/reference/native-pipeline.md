# Native execution reference

The native backend builds an explicit execution plan and runs it through the durable stage supervisor. Planning validates the requested physics family, cards, detector adapter, routine, and statistical mapping before generation. It prints `compute_authorized: false`; a plan records a proposed computation and does not grant approval or certify physics.

Native analysis admission discovers versioned analysis-package manifests: the packages shipped
under `src/ravel/data/analysis_packages/` and any **supplied** roots. The shipped population is
four named selections: three reconstructed-event routines and one calibrated-event projection
(listed by `discover_capabilities()`); every one carries qualification `pending` until a bound
report says otherwise, so the planner refuses it with `missing_package_qualification`.
Select `ravel.native.analysis_package` explicitly. `RAVEL_ANALYSIS_PACKAGES` adds discovery roots
(a supplied package that repeats a shipped identity refuses as ambiguous, it does not override)
and `RAVEL_NATIVE_ALIASES` can bind upstream names to discovered package identities. Discovery
reads manifests and source commitments without importing selection code. A missing package,
mismatched compatibility predicate, changed source, or missing qualification evidence refuses
admission with a typed reason. A shipped package is a selection and its declared interface; it
is neither a physics certificate nor an execution approval.

## Configuration

Every configuration supplies model, preparation, detector, statistics and analysis-package bindings.
All physics values, event counts, parameter points, cards and destinations come from the study.
The supported pipeline interfaces are `explicit-cards`, `simpleanalysis-delphes`, and either
`yields` or `mapped-likelihood`. A package must explicitly admit the requested combination.

```toml
[ravel.native]
model = "<declared production family>"
preparation = "explicit-cards"
detector = "simpleanalysis-delphes"
statistics = "<yields or mapped-likelihood>"
analysis_package = "<supplied manifest path>"

[ravel.native.inputs]
process_card = "<supplied process card>"
param_card = "<supplied parameter card>"
run_card = "<supplied run card>"
shower_card = "<supplied shower card>"
delphes_card = "<supplied detector card>"
```

Also supply `[madgraph.run]` event count, seed and collision energy; `[analysis]` luminosity
in inverse pb, correction factor and the Delphes conversion interface; and
`[simpleanalysis] name` matching a selected package identity. Paths resolve relative to the
run directory. A mapped likelihood requires its supplied workspace, complete channel map,
and explicit finite-MC policy. No legacy identity infers an adapter or a channel map.

The package declares its interface version, source digest, region order, flavour flags,
compatibility predicates, helper outputs and argument list. Counting selections use
`sr_order()` and `select(arrays, index)`; two-pass selections expose `run(argv)`;
calibrated selections expose their state validator, region decisions and era semantics.
Source files, manifest and qualification evidence enter the plan's source commitments and
supervised stage inputs. The common `native_simpleanalysis` frontend requires
`--analysis-package` and `--execution-plan`; it verifies current approval and the running
supervised stage before importing the selected body. New source bytes require a new plan
and prospective approval. A supplied package is reviewed executable input.

Package qualification is an interface-scoped supplied record, not a physics certificate.
Each evidence pin must identify a passed `routine-qualification/v1` record with the selected
source digest, interface version, matching compatibility scope and complete successful checks.
Pending packages cannot enter native execution. Qualification against supplied references,
detector acceptance, model validity and statistical certification remain separate obligations.
The shipped selection sources are stored as `selection.py.txt` beside their manifests so that
they are data, not importable product modules; the manifest pins the exact bytes. They carry
pending qualification, never past run results.

The explicit-card adapter accepts bounded unmerged LO `MSSM_SLHA2` production. It checks proton initial states, two produced particles from the declared family, model masses, positive parent widths, and explicit branching rows to the LSP. Branching fractions must sum to one. For a scan, supplied masses must agree with the selected point. A different point needs its own parameter card. The process card may contain model import, aliases, settings, and generation commands; output and launch commands are generated by Ravel. Alias definitions must precede generation. No slepton template is substituted for a different model.

The process card must use one jet multiplicity. Combining separate unmerged zero-jet and one-jet samples would double-count phase space; that requires a matching/merging adapter. Chargino–neutralino aliases must retain associated production in each final-state slot. A zero-parton process also rejects positive `ptj1min` or `htjmin`: those MadGraph cuts require a jet and can otherwise produce zero cross section despite an apparently valid inclusive process.

The run card must explicitly provide `nevents`, `iseed`, both beam energies, `ickkw = 0`, a PDF choice, and disabled additional systematic weights. Counts, seed, and energies must agree with the TOML. The shower card must declare `Beams:frameType = 4` and `Beams:LHEF`; Ravel binds that path to this run's generated events. Matching and merging settings require a separate adapter. The input cards are preserved unchanged.

For a local Darwin `NNPDF30_nlo_as_0118` central-member study, explicit cards can
add `lhapdf_linker = "preserve-activated-v1"` and the corresponding
`lhapdf_link_decision` input. Follow the [metadata capture and linking procedure](../../reference/native-portability.md#lhapdf-linking-for-an-explicit-native-study)
before planning. This opt-in path preserves the activated compiler flags, checks
the selected library/PDF sources again inside the generator environment, and
declares the linker execution record as a MadGraph output. Existing plans keep
their declared PDF and commands. A metadata decision never grants generation
approval or validates the resulting physics.

For a new unmerged nominal study that needs exact original-event identity, set
`lhe_provenance = "original-v1"` in `[ravel.native]` alongside
`preparation = "explicit-cards"`. Build the updated shower wrapper in a source
checkout and bind that separately produced binary in the new plan. The policy
supports both plain and gzip event storage; it keeps the canonical twelve-stage
sequence and adds `output/madgraph/original-lhe.jsonl` and
`output/madgraph/lhe-provenance.json` to the shower stage's declared outputs.

The sidecar records Pythia's existing original-LHA fields without replacing its
reader, changing random-number calls or adding retries. The owned successful
producer, complete original LHE, exact content/order, full HepMC decoded EOF,
counts, file descriptors and current input/source bytes must agree before the
report is published. Ambiguous duplicate original content, auxiliary event XML,
matching/merging, missing sidecars and source drift reject. Failed outputs remain
available for diagnosis. File storage and native compilation may temporarily
use extra disk; include that peak and failed attempts in resource admission.

This is an identity contract. It does not calibrate the shower, prove a compiler
history from a source file, validate a signed-weight uncertainty estimator or
claim equality to an earlier HepMC stream. New reports explicitly record that
replay byte equality was not performed. Existing plans retain their original
commands and receipts. Wheel-only use without the required wrapper source
contract is rejected; use the source checkout and a new reviewed build/plan.

For `mapped-likelihood`, provide `likelihood` and `channel_map` paths under
`[ravel.native.inputs]`. The map covers every workspace channel exactly, using an explicit
region/flavour or null for declared zero signal. Region and flavour membership come from the
selected manifest. Signal injection uses the workspace's unambiguous, signal-only POI.
Overlapping regions must not be advertised as independent likelihood channels by a package.
Missing mappings refuse; channel names and analysis identities never imply selection semantics.

Preparation is selected explicitly and separately from analysis. The card renderer is an
independent preparation interface with its own supported inputs; a routine identity never
selects it. Supplied explicit cards retain their normalization and generation safeguards.

## Effective physics settings

New plans carry `output/native_effective_settings.json`. It binds prepared process, run,
parameter, shower and detector cards, relevant source identities, requested controls, and exact
planned commands. Preparation emits it; downstream execution and reuse check it. A missing or
changed manifest/card stops execution. Requested software versions are recorded as intent;
a configuration version label does not prove the binary actually ran that version.

The narrow legacy slepton adapter resolves declared mapyde card locations and applies supported
Pythia settings, MPI selection and additional options. It translates only known inactive interface
sentinels in an unmerged card and records each translation. Unsupported active matching/merging,
conflicting controls or an incompatible process are rejected. When absent from that legacy route,
`Tune:pp = 14` and `PartonLevel:MPI = on` are labelled adapter choices, not evidence of historical
or author-recipe equivalence. Explicit native cards receive no baseline overlays and are preserved
except for the managed LHE path. Generator seed activation is recorded explicitly.

This fixes an earlier narrow adapter that emitted only the LHE path, beam mode and quiet flag
from a legacy request and could silently omit shower options. Prepared-byte agreement is only
configuration fidelity. Successful receipts can establish command/input/output binding; neither
is independent observation of a simulator's internal state or validation of detector physics.

For a rejected scientific result, follow the [bounded correction protocol](physics-review.md).
The corrected plan and effective manifest must be prospectively listed as mutable effective
settings and frozen in the admission. The unchanged first approval still limits events, points,
model, masses, detector and statistical scope. Only the exact admitted stage subset may run;
preparation is completed before admission and is refused during it. Historical plans remain
inspectable without silently acquiring new effective-setting validation.

## Plan, execute, and resume

Use Python from the installed Ravel environment. These commands work from outside the source checkout after ordinary or editable installation.

```bash
python -m ravel.physics.native_pipeline plan \
  --rundir /absolute/run --config config.toml

# Persist the reviewed proposal in inputs/native_execution_plan.json.
python -m ravel.physics.native_pipeline plan \
  --rundir /absolute/run --config config.toml --write

# Execute only after the study's compute approval.
python -m ravel.physics.native_pipeline run \
  --plan /absolute/run/inputs/native_execution_plan.json
```

Before execution, the task contract must include `execution_plan: {"path": "inputs/native_execution_plan.json", "sha256": "<SHA256 of the saved file bytes>"}`. Record the user's actual approval with `workflow_state approve` after the CHECK-IN 1 and cost artifacts are complete. The executor verifies their current content binding and checks model, analysis, detector, statistical outputs, masses, luminosity, and event/point/backend budget against this exact plan. Missing or older unbound contracts remain held; execution never fabricates or renews approval. A smoke approval cannot cover more than 1,000 events or a multipoint campaign.

For scans, `scan_orchestrator launch <scan-dir> --backend native --write-plans` persists proposals without running tools. Each point's contract pins its own saved plan and approval. Add `--go` after approval; add `--resume --go` to include repaired failed/interrupted durable points. A native plan is never rewritten by the executor after approval.

The source-tree convenience wrapper `bash native/scripts/run-pipeline-native.sh /absolute/run config.toml` invokes the same planner and executor. `RAVEL_PYTHON` can select the Ravel Python interpreter. Native backend locations use `RAVEL_NATIVE_BUILD` and `RAVEL_NATIVE_BIN`; see `native/scripts/paths.sh`. The selected conda executable, environment prefixes, generator, shower, detector, converter, and the RestFrames resolver when selected are declared dependencies. Missing or non-executable required tools stop execution before the first stage.

The recommended native PDF default is `NNPDF30_nlo_as_0118` (LHAPDF `260000`, preparation choice `--pdf nnpdf30`). This matches `native/setup/pdf-sets.json` and the generation run-card checklist. Plans still require an explicit PDF choice and the selected set/linker prerequisites; a reference recipe may require another basis. PDF changes can change acceptance and require validation.

Each plan contains ordered stages with `stage`, `command`, `inputs`, `outputs`, and `depends_on`. The chain is:

1. Materialize the declared cards.
2. Generate in a fresh, retained `<rundir>/work/madgraph/attempt-*` directory.
3. Unpack the stable `output/madgraph/unweighted_events.lhe.gz` while preserving it.
4. Run the mandatory LHE mass/card/structure gate.
5. Shower the requested event count to HepMC.
6. Resolve and record normalization evidence.
7. Run Delphes and convert its nominal weights to the SimpleAnalysis ntuple.
8. Execute exactly the selected routine, writing `output/<Routine>.root` and `.txt`.
9. If requested, make the signal patch and run likelihood inference.
10. Write `output/native_execution_result.json`, identifying the actual routine, model, statistical adapter, plan hash, and output hashes.

The final report does not invent an exclusion for yields-only runs. Statistical runs also produce `output/exclusion.json`.

Re-running the same `run --plan` command resumes by checking input, code, runtime, dependency, and output receipts in `execution_state.json`. Only a matching successful stage is reused. Original sources are rechecked before every stage; changing a card invalidates the saved plan. After a deliberate input change, build and review a new plan, update its contract pin, record renewed actual approval, then run it. Retries archive prior declared outputs and logs under `logs/execution/<stage>/<attempt>/`. MadGraph gets a new working directory, so it neither prompts to overwrite an old PROC nor deletes an unpacked downstream LHE. Earlier process directories remain available for diagnosis.

There is no unsupervised fallback. A nonzero exit, invalid output, unresolved normalization, or failed dependency stops downstream stages. A quiet log alone is not proof of a stalled job. The supervisor uses process ownership and bounded termination for interrupted attempts. Do not delete `STATUS.txt`, receipt files, or intermediate dependencies to force a retry. The babysitter retains all artifacts for execution-ledger runs; held failures require input/tool repair followed by supervised resume. Disk planning must include retained attempts and receipt dependencies.

Read-only receipt validation reuses freshly computed hashes only within one
validation call. It checks each expected digest, revisits file identities and
directory membership before returning, and verifies the final ledger through its
opened descriptor and pathname. Later calls hash again. This reduces repeated
work across shared ancestors without treating timestamps as content evidence or
claiming an atomic filesystem snapshot. Generation accounting identifies the
run's own canonical plan; another source-bound plan with the same filename stays
provenance and cannot determine that run's charged event count.

The canonical scan dispatcher supports container commands as dry diagnostics only. Live `--backend container --go` is refused until a container adapter can bind its exact inputs and outputs to approval. It cannot bypass the native approval boundary.

## Normalization and scientific limits

The authoritative generated cross section is the LHE init-block rate in pb. The parser distinguishes the declared numeric subprocess rows from well-formed XML generator metadata; malformed numeric tails and duplicate subprocess identifiers fail. A MadGraph log summary, when present, must corroborate the rate within its printed precision. The native shower must explicitly report a compatible rate in mb and preserve the requested event count. A missing rate never becomes 1 pb. Luminosity is required in inverse pb, and a finite positive correction is required explicitly; corrections below one are valid. `XSoverride` is rejected by this adapter.

`output/normalization.json` records the generated rate, the correction applied once, the corrected rate, event count, signed weight moments, and hashes of its evidence. Signed individual nominal weights are preserved, but the total must be positive and finite. The converter checks event counts, weight signs, relative weight moments, every converted nominal weight, and the final weight sum. It writes `Delphes2SA.root.normalization.json`; luminosity remains unapplied in those ntuple weights and is applied once when producing signal yields for inference.

These checks establish bookkeeping consistency within the bounded adapter. They do not prove that a generator, PDF, shower tune, detector card, or correction is experimentally accurate. Older container parity observations remain historical evidence for their exact artifacts, not universal certification of new generation or new cards.

The shared Delphes converter writes all lepton ID bits set because that detector representation does not emulate those quality decisions. It also maps a generic nonzero Delphes b-tag into several distinct SimpleAnalysis working-point flags. This does not supply separately calibrated ATLAS taggers or efficiencies at each working point. An analysis requesting an 85% working point therefore still needs evidence for the physical response represented by the supplied card. Changing either behavior is a detector-model change requiring validation. Acceptance certification and current experimental comparison are separate from executable registration and successful receipts.


## Compressed-signal diagnostics and event retention

For an explicit native compressed-slepton configuration, `[ravel.native]` accepts
an explicit `compressed_signal_model = "full"` or `"sr-only-diagnostic"`.
The full adapter validates its declared slepton SR/CR map before generation and requires
all six control-region branches. The diagnostic mode records their omission. Other
compressed analyses need a complete explicit channel map; names are not a license to
invent control-region yields.

Declare `mc_stat = "shapesys"` or `"staterror"` to include independent-bin signal MC
constraints from the actual selected sumw/sumw2. Explicit `"none"` records that the
uncertainty is omitted. `output/signal_model.json` retains channel mappings, moments,
effective counts, zero-selected precision warnings and input/patch hashes. These
constraints do not provide detector, trigger, ISR or theory nuisance responses. Repeated
ROOT inputs are additive process components only when declared; independent-seed replicas
require generated-exposure-aware pooling and same-process evidence.

`event_storage = "gzip"` makes the shower's durable output compressed HepMC from birth.
The wrapper validates native event framing/counts and a lossless byte round-trip, retains
a storage receipt, and streams decompressed bytes through Delphes' stdin interface.
`"plain"` preserves the existing storage mode. Temporary uncompressed bytes belong only
to the producing stage; no receipted dependency is compressed or deleted in place. Budget
retained gzip, LHE, detector and analysis ROOT, traces and failed attempts, together with
the temporary plain output of concurrent showers. The cost-preflight transient estimate
is not a whole-campaign retention estimate.

`pyhf_backend = "numpy"` (default) or `"jax"` explicitly selects the tensor backend.
The native defaults use the rivet and recast environments respectively. An absolute
`statistics_python` path may select an isolated statistics interpreter without changing
the HEP toolchain. It must contain the requested backend and guarded-optimizer dependencies;
a missing dependency is a failure, not an automatic backend substitution. The interpreter
is a planned input, and the statistical result records dependency versions and inputs.
The virtual-environment configuration is also pinned when present. This is not a complete
lock of every imported package and shared library; retain the environment inventory with
the run. The guarded fit validates finite objectives, constrained stationarity, profile
nesting and freshly evaluated roots after freezing its finite set of candidate starts.
It does not prove a global optimum or establish asymptotic coverage in sparse bins.

## Independent replicas and response diagnostics

`ravel.physics.pool_replicas` combines independently seeded replicas of the same explicit
unmerged, uniform-positive LO process. A manifest supplies each run's saved native plan
and its hash. The helper verifies historical ancestor receipts, cards, tools, original
exposure and ROOT weights; all three generation/shower/detector seeds must differ.
For replica j it uses `alpha_j = N_j / sum(N)` and multiplies every original event weight
by alpha_j. Squared weights scale by alpha_j squared. Adding already normalized replicas
would incorrectly add multiple estimates of the same cross section.

```bash
python -m ravel.physics.pool_replicas --manifest /absolute/replicas.json \
  --out /absolute/new-pooled-output
```

The output preserves source event IDs and replica indices under globally unique event IDs.
Its `sqrt(sumw2)` uncertainty is a Poissonized independent-event approximation; it is not
the exact fixed-exposure binomial variance or a generator integration uncertainty. The
helper refuses common-random-number controls, merged/NLO samples and changed physics.

`ravel.physics.truth_reco_response` provides an event-linked response diagnostic
with supplied binning, particle flavours, ancestry relations, origin labels and
topology rules. Invoke `python -m ravel.physics.truth_reco_response --contract
<response-contract.json> --input <events.root> --detector-card <card> --output-dir
<output>`. The contract supplies its study identity, parameter grid, dataset
population, `output_format` (`json` or `jsonl.gz`), momentum/absolute-eta edges,
flavours, parent relations, ancestor categories, origin labels, stable-particle
codes and topology checks. Native joins additionally require `--join-contract`
with source pins, predicate/region membership and unavailable-predicate rules.
The direct slepton-lepton contract ships as `src/ravel/data/analysis_assets/response/
slepton-direct-lepton.json`; `ravel.physics.shipped_assets.response_contract(four_state=...)`
returns it validated (`four_state=False` drops the production-topology rules). Its
binning is a diagnostic grid, not a calibrated efficiency map.
The entire original population remains, including unmatched particles and topology
violations. Signed weights and shared-event ratio moments remain explicit;
boundary counts stay precision unresolved.

Production-origin accounting requires `origin_accounting` in its pinned plan,
including its supplied `contract`, complete channel `mapping` and source artifact
paths. Categories, ancestry overlays, trace prerequisites and channel populations
come from this input; no model identity or fixed channel count enables accounting.
Original normalized exposure and channel/patch moment closure remain required.

For retained native observations, select the supplied
[instrumentation and classifier package](../../reference/analysis-response-features.md),
[fill-site schema](../../reference/native-group-acquisition.md), or
[cumulant mapping](../../reference/native-cumulants.md). These read-only consumers
and source preparations establish neither native execution authority nor physics
certification. A detector-card hash alone does not establish production provenance;
retain the ordinary production receipt chain with any response claim.



## Required native claim inputs

Every native likelihood plan, and every plan with an `exclusion` claim in
`inputs/plan.json`, requires both `mc_stat` and `compressed_signal_model` in
`[ravel.native]`. Missing choices are reported together before preparation.
Yield-only studies retain diagnostic defaults; those defaults do not authorize
an exclusion. The signal-patch CLI requires `--mc-stat` and, with `--compressed`,
`--compressed-signal-model`. Omitting MC uncertainty or control-region signal
is an explicit approximation, not evidence of agreement.

An `agreement` claim in `inputs/plan.json`, or `task_mode = "reproduce"` in
`inputs/task_contract.json`, requires a declared `native.inputs.delphes_card`
or `delphes.card`. The adapter refuses an implicit detector card. These
requirements are checked again when loading a plan, including after intake
records change. Declaring a card does not establish detector calibration.

Every prepared shower card enables `Random:setSeed` and writes a fixed positive
`Random:seed` in `1..900000000`. A valid explicit shower seed is preserved.
Otherwise the positive generation seed is reused; absent or automatic generation
seeding selects the disclosed fixed shower seed `1`. Disabled or time-based
shower seeding is refused. Managed seed additions affect prepared copies only.
Both plain and gzip producers record the consumed card hash, seed, successful
exit and complete event count in `<HepMC output>.shower.json`. Gzip storage
receipts and original-event provenance reports also retain the seed.

The recipe ledger consumes `requested_controls.tool_version_labels` in
`output/native_effective_settings.json`. Each supplied version label carries
`declared` and `disposition = "label_only_native_runtime_version_unverified"`.
Labels do not select or authenticate installed runtimes. The ledger must compare
them with independently observed versions, retain missing observations as unknown,
and record a mismatch as a deviation.

## Recipe ledger before full execution and at delivery

Inspect the current recipe without running tools:

```bash
python -m ravel.workflow.recipe_ledger --rundir <run>
python -m ravel.workflow.recipe_ledger --rundir <run> --write
python -m ravel.workflow.recipe_ledger --rundir <run> --check-full
python -m ravel.workflow.recipe_ledger --rundir <run> --checkin3
```

The ledger enumerates every critical pointer of each request-plan operation and
compares declared controls, inherited rendered-card settings, current card hashes,
mass/width values, tool-version observations and signal-patch metadata. The native
producer's cards are read again; cached effective values cannot establish a match.
A missing setting in a readable card is a deviation, even when the requested value is
null. Each key of a request node's `/generation/run_settings` or `/generation/shower`
map has a `translation` row: the read card decides it, or the native requested side
when no card has been read. An option the native translation dropped is therefore
`deviated` and blocks the full launch until it is authorized. A missing observation is
unknown. Neither prepared settings nor version-label text proves runtime
consumption, installed-tool authentication, detector calibration or physics agreement.

The trusted CHECK-IN registry inserts `recipe_ledger` at CHECK-IN 1. CHECK-IN 1
binds the requested side of every row. Status and effective values are current
evidence, so an `unknown` row that later becomes correctly `matched` keeps the
approval valid. A changed requested value, or a requested row the CHECK-IN 1 did not
show, refuses it. Every deviated row needs either a numbered flag whose
`recipe_deviation` equals `recipe_ledger.deviation_payload(row)`, or a current accepted
RDJ receipt. Flag text must explain the choice. At the launch gate, flag authorization
also requires a valid, current CHECK-IN 1 approval. For an epoch-2 contract, the launch
also refuses when `inputs/native_execution_plan.json` exists but the task contract does
not pin it as `execution_plan`. `--write` retains separately hashed deviation
payloads in `outputs/recipe-deviations/` and the current ledger in
`outputs/recipe_ledger.json`. Use `deviation_action(rundir, row)` to open an RDJ
`deviation` case with action kind `tuning_change` and the applicable tuning class.
The consumer calls `rdj_loop.authorizing_receipt`; an authored receipt JSON or a
receipt for different bytes cannot authorize the row. The receipt authorizes only within
its tuning class: the case must be a `tuning_change` of class `recipe_restoration`,
`implementation_correction` or `new_approximation`, and `calibration` is accepted only for
detector rows. The receipt must also carry a custody human approval. Revised payloads
retain the original files. Evidence paths inside the run are stored run-relative, so a
symlinked, `/tmp` versus `/private/tmp` or moved run keeps its flags and receipts.

Effective operation values and tool versions can be supplied through
`inputs/recipe_observations.json`: `observations` is a list of
`{layer, node_id, field, receipt_id, pin: {path, sha256}, pointer}` records. `field`
identifies the ledger's JSON pointer; `pointer` selects the observed value in the pinned
producer JSON. Use layer `operation` with its plan node ID, or `tool_versions`
with a null node ID. The observation list is only an index. A value counts only when its
pinned file is listed, with that sha256, in the registered and current stage receipt
`receipt_id` (`stage:<name>:<attempt_id>`), and that stage's command is a recognized RAVEL
module or native tool (`custody_authority.stage_output`). A file the agent wrote, a copy of a
plan text, an authored script's output, or changed or missing bytes all stay
unknown. No version command is executed by the ledger. A version-probe producer is not yet
shipped, so version rows stay unknown until a stage writes them.

Agreement-target recipe pins may supply JSON with `layers` (layer names to setting mappings)
and `card_hashes` (card names to hashes). Reference rows retain their claim ID.
Unmapped or remote recipe pins remain unknown; the ledger never downloads or
guesses a recipe. Detector details without observations, including tagging,
lepton flags, trigger, pile-up and JVT, remain visible as unknown.

At CHECK-IN 3, compose the record with
`recipe_ledger.with_checkin3_section(document, rundir)`. The section lists all
unknown and deviated rows and the matched count. The delivery validator calls
`checkin3_errors`, refusing omitted or changed disclosure and any current deviation
without authorization. The CHECK-IN registry
currently composes CHECK-IN 1 only; delivery composers must use this explicit
callback. Downstream consumers read current `recipe_ledger.rows(rundir)`.

Automatic CHECK-IN enforcement is mandatory for epoch-two contracts. Historical
epoch-one contracts retain their existing check-in bytes and gate decisions;
explicit ledger inspection and composition remain available for their inputs.
An absent contract does not suppress a ledger when prospective recipe inputs exist.

## Comparing supplied qualification values

The manifest structure is `src/ravel/data/analysis_packages/manifest.schema.json`.
Prepare numerical computed values, reference values and per-quantity `rtol`/`atol` policies
as supplied JSON objects with identical quantity keys. Then run:

```bash
python -m ravel.physics.analysis_packages qualify --manifest <manifest> \
  --reference <reference.json> --computed <computed.json> \
  --tolerances <tolerances.json> --output <new-report.json>
```

The comparator performs no native execution and installs no reference population. It binds the
selected source and compatibility scope, reports every comparison and returns nonzero on failure.
Retain the report outside the product repository and add its exact digest to a supplied manifest's
qualification evidence only after review of the reference source and the qualification scope.
The report establishes the supplied comparison, never general detector or model certification.
